# Известные ограничения

Здесь честно перечислено то, что **не** проверено или **не** работает.
Ничего из этого не скрыто и не имитируется.

---

## 1. Что проверено настоящим запуском, а что — нет

### Проверено: игра реально запускается и загружает наш мод

В песочнице нет монитора, но есть `Xvfb` и программный OpenGL Mesa
(`llvmpipe`, OpenGL 4.5 Core). Стенд `tools/harness/HeadlessRun.java` ставит
игру кодом лаунчера и запускает её. Что получено на самом деле
(выдержки — в [`docs/VERIFICATION_LOG.md`](VERIFICATION_LOG.md)):

```
[main/INFO]: Loading 91 mods:
[Render thread/INFO]: [Aurora] AetherGlass Client 1.0.0: запуск
[Render thread/INFO]: [Aurora] настройки прочитаны: загружено параметров: 7, пропущено строк: 0
[Render thread/INFO]: [Aurora] обработчики отрисовки мира подключены
[Render thread/INFO]: [Aurora] AetherGlass Client готов: Minecraft 1.21.11, загрузчик 0.19.5
[Render thread/INFO]: OpenGL Renderer: llvmpipe (LLVM 19.1.7, 256 bits)
[Render thread/INFO]: Reloading ResourceManager: vanilla, aetherglass, badoptimizations,
                      c2me, dynamic_fps, entityculling, fabric-api, … trender
```

То есть: установка работает, командная строка работает, Fabric Loader
поднимает 91 мод, наш мод инициализируется, читает настройки и подключает
обработчики рендера.

**И главное — прогон нашёл настоящий баг**, который ни сборка, ни тесты не
показывали: `ModInstaller` не устанавливал Fabric API, и игра отказывалась
стартовать (`Mod 'TRender' requires any version of fabric-api, which is
missing!`). Исправлено, добавлены проверка зависимостей и два теста.
Подробности — в [`docs/BUILD.md`](BUILD.md).

### Не проверено: как выглядит меню

До титульного экрана игра **не дошла** ни в одном из четырёх прогонов:
загрузка останавливается на создании текстурных атласов и компиляции
шейдеров, которые на двух ядрах без видеокарты идут десятки минут
(процесс при этом жив и грузит процессор на 100 %). Это ограничение железа
песочницы, а не кода, но честнее сказать так: **картинку глазами никто пока
не видел** — ни я, ни ты.

**Контрольный прогон это подтвердил.** Запуск без десяти оптимизаций
(только Fabric API и наш клиент) останавливается **на том же самом месте** —
сразу после `Created: … shulker_boxes.png-atlas` — и показывает ровно ту же
статичную картинку, что и полный прогон. Значит, причина не в нашем моде и не
вSodium с компанией, а в программном OpenGL на двух ядрах без аппаратного
ускорения. Ошибок миксинов и сбоев нашего клиента в журнале нет:
`Reloading ResourceManager` проходит, клиент инициализируется, исключений нет.

Что ещё можно сделать: запустить игру на машине с настоящей видеокартой
(или хотя бы с аппаратным GL) — это займёт минуту и покажет меню целиком.

### Как проверялось всё остальное

| Что | Как |
|-----|-----|
| Мод загружается Fabric Loader'ом | настоящий запуск, см. журнал выше |
| Миксины применены к нужным методам | в собранном jar миксины содержат intermediary-имена (`class_310.method_1507`, `class_759.method_22976`, `class_9975.method_74926`); ранее с `-Dmixin.debug.export=true` в `.mixin.out` появлялись изменённые классы игры |
| Сигнатуры методов игры | `javap` по `minecraft-named.jar` (распакованная игра с маппингами 1.21.11) |
| Сигнатуры Fabric API | исходники Fabric API 0.141.6+1.21.11 |
| Логика без графики | 25 автоматических тестов (см. `docs/BUILD.md`) |

## 2. Вход в аккаунт требует идентификатор приложения Azure

Поток Microsoft → Xbox Live → XSTS → Minecraft реализован полностью и по
настоящему (это не «заглушка», код делает реальные запросы). Но для него
нужен **client id приложения, зарегистрированного в Azure** — он указывается
в `launcher/src/main/java/com/aurora/launcher/auth/MicrosoftClientId.java`.

Без него сервер Microsoft вернёт ошибку, и лаунчер покажет её текстом.
Мы не подставляем чужой идентификатор: это было бы использованием чужого
приложения и могло быть заблокировано в любой момент.

**Что сделать:** зарегистрировать своё приложение в Azure
(тип «общедоступный клиент», разрешение `XboxLive.signin`) и вписать
идентификатор. Пароль вводить и хранить не нужно ни при каком раскладе.

## 3. Версия игры зафиксирована

- Мод клиента и все 10 оптимизационных модов собраны под **1.21.11**.
- В `fabric.mod.json` стоит зависимость `minecraft: 1.21.11` (ровно эта версия),
  поэтому на другой версии Fabric Loader откажется грузить мод с понятной ошибкой.
- Лаунчер умеет показать список версий из официального манифеста Mojang и
  установить любую из них, но Aurora-мод заработает только на 1.21.11.

Это сделано намеренно: подмена версии без проверки — именно то, чего в задании
просили не делать.

## 4. Маппинги

Yarn для 1.21.11 отсутствует — `meta.fabricmc.net/v2/versions/mappings/1.21.11`
отвечает `Not Found`. Поэтому используются официальные маппинги Mojang
(`loom.officialMojangMappings()`), а ремап миксинов делает Fabric Loom в задаче
`remapJar` (проверено по содержимому jar).

Побочный эффект: названия полей и методов в коде — официальные, местами
неочевидные; там, где это было важно, в коде оставлены пояснения.

## 5. Ограничения эффектов

| Эффект | Ограничение |
|--------|-------------|
| Частицы | Рисуются в слое прозрачности, поэтому корректно видны сквозь воду и стекло, но **не** перекрывают уже нарисованную непрозрачную геометрию — это нормально и соответствует слою. |
| Подсветка блока | Контур строится по настоящим рёбрам формы блока, но число рёбер и параллелепипедов ограничено (768 и 64) — у форм сложнее предел просто обрежет хвост. |
| Частицы у блоков | Ищутся в радиусе до 32 блоков, максимум 24 блока за проход, с ограничением частоты. За пределами радиуса эффекта не будет. |
| Эффекты рук | Оверлей рисуется поверх ванильной модели, поэтому не может «выйти за» её геометрию — свечение добавляется вокруг, а не заменяет модель. |
| Эффекты рук | **Пиксельная обводка по силуэту пока не реализована** — тому есть точная причина, см. раздел 7 ниже. Сейчас работают поза, свечение, градиент и акценты по реальной геометрии руки. |
| Небо | Меняются цвета состояния рендера неба. Глубина эффекта ограничена тем, что отдаёт игра: мы не подменяем сам шейдер неба (это был бы шейдерный мод). |
| HUD | Пинг берётся из данных сервера; в одиночной игре показывается прочерк. «Кадры в секунду» и память — реальные измерения процесса, а «загрузка процессора» — оценка по времени кадра. |

## 6. Лаунчер

- Лаунчер — нативный exe (Go + walk), а не Java-программа: никакой Java для
  самого лаунчера не нужно, Java ставится только для игры.
- Интерфейс — обычные окна Windows (Win32), поэтому он выглядит как системный,
  а не как «нарисованное» окно на Swing. Единое оформление с меню игры
  держится на общих приёмах (стекло, градиенты, упругие элементы), но
  по-прежнему делается вручную.
- Окно лаунчера ни разу не показывалось на реальном Windows: в сборочной
  песочнице нет графического окружения, проверяются код, сборка и тесты.
- Отмена скачивания прерывает загрузку файлов; уже скачанные файлы остаются
  на диске и переиспользуются при следующем запуске (это особенность, а не баг).

## 7. Прочее

- Обратной совместимости со старыми версиями конфигурации нет: при смене
  формата старые ключи просто игнорируются (значения берутся по умолчанию).
- Сетевые запросы в лаунчере не используют прокси из настроек операционной
  системы — при работе через прокси потребуется указать его в переменных
  окружения Java.
- Клиент не взаимодействует с сервером: это полностью клиентский мод,
  он ничего не отправляет на сервер и не даёт игровых преимуществ.

## 7. Почему обводка рук пока не по силуэту (и что для этого нужно)

Требование понятное: обводка должна повторять настоящий силуэт руки и предмета,
а не быть рамкой на экране. Проверил по байткоду игры, что для этого доступно
в 1.21.11, — и честно фиксирую результат:

| Путь | Что показала проверка |
|------|-----------------------|
| Своё окно рендера (FBO) + свой GLSL | Классы есть и работают: `TextureTarget`, `RenderPipeline` со своими шейдерами, `RenderPass`, `Std140Builder`, `GpuSampler`. Перенаправление вывода тоже есть: `RenderSystem.outputColorTextureOverride` — его читает сам `RenderType.draw` (видно в байткоде). **Но** руки в 1.21.11 рисуются не напрямую, а через `SubmitNodeCollector`, у которого нет публичного метода сброса: узлы уходят на GPU позже, внутри `GameRenderer`. Значит, момент, когда нужно включить и выключить переопределение, из мода не контролируется — получится либо пустая маска,либо двойная отрисовка руки. |
| Свой тип рендера с плоским цветом | `RenderType.create` в 1.21.11 **пакетный** (`static`, без `public`) — из мода его не вызвать. |
| Классический «вывернутый корпус» (inverted hull) | Нужно отсекать передние грани. `RenderSystem` больше не управляет `cullFace`, у `RenderPipeline.Builder` есть только `withCull(true/false)` — какая именно сторона отсекается, из публичного API не задаётся. |

Что остаётся рабочим путём (и он реализуем): свой `RenderPipeline` со своим GLSL
плюс самостоятельная тесселяция геометрии модели предмета (расширенная оболочка,
запись глубины выключена, рисуется **до** ванильной руки — тогда оболочка видна
только там, где руки нет, то есть ровно по силуэту). Для этого нужно
верифицировать по байткоду: публичный метод `ItemInHandRenderer.renderItem(...)`,
получение модели предмета и формат вершин модели в 1.21.11.

Это не «заглушка»: сейчас эффекты рук — это реальная геометрия (поза, свечение,
градиент, акценты), а не картинка поверх экрана. Пиксельная обводка по силуэту
будет доделана следующим шагом и появится отдельным режимом, а не заменит
нынешнее поведение молча.
