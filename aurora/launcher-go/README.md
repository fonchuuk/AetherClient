# AetherGlass Launcher (нативный)

Лаунчер — обычная программа Windows. Никакой Java, никаких jar-файлов:
исходники на Go, интерфейс — страница в движке Chromium (WebView2), один
exe на 8,5 МБ.

## Почему так

Первая версия лаунчера была программой на Java, завёрнутой в exe. От неё
остались три болезни, которые невозможно вылечить косметикой:

- exe не запускался без Java 21, поэтому рядом лежал каталог `runtime` на 49 МБ;
- exe приходилось распаковывать (50 МБ при каждом запуске), чтобы добраться до
  jar внутри;
- `javaw -jar` должен уметь читать zip из середины PE-файла — любой антивирус,
  который в этот момент держит только что созданный exe, ломает запуск
  («Unable to access jarfile»).

Нативный exe снимает всё сразу: он один, он запускается мгновенно и не требует
ничего, кроме Windows. Java нужна только самой игре (Minecraft — игра на Java):
её лаунчер найдёт в системе либо скачает официальный рантайм Mojang при
установке игры.

## Как устроено

```
core/     — вся логика без интерфейса: каталоги, настройки, загрузки,
            установка игры, моды, вход Microsoft, запуск.
            Собирается и под Linux, поэтому проверяется тестами (29 штук).
uiweb/    — окно (WebView2) и сама страница webui/index.html.
            Включается в exe через //go:embed. Только под Windows.
assets/   — иконка, манифест Windows, mods.json и вложенный мод клиента.
build.sh  — сборка exe.
```

Страница общается с Go через привязанные функции (`view.Bind`): `login`,
`install`, `play`, `downloadJava`, `saveSettings` и остальные. Каждый вызов
Go уходит в отдельный поток, поэтому интерфейсная нитка никогда не блокируется,
а состояние приходит на страницу одним объектом JSON (`AetherGlass.state`).

## Как сделано стекло (Liquid Glass)

Интерфейс не «нарисован под стекло» — он показывает сквозь себя то, что у него
за спиной, и делает это движок Chromium на видеокарте:

1. **Фон.** Пять медленно плывущих пятен (синие, фиолетовые, бирюзовые) на
   почти чёрном синем. Двигаются свойством `transform` — его считает
   видеокарта, процессор не трогается.
2. **Размытие подложки.** `backdrop-filter: blur(26px) saturate(180%)
   brightness(1.12)` — фон под панелью размывается и подсвечивается по-настоящему,
   а не «плёночкой» поверх.
3. **Преломление.** SVG-фильтр `feDisplacementMap` по карте `feTurbulence`
   сдвигает пиксели подложки у кромки на 15 px. Это физическое искажение
   изображения, а не размытие — тот самый «загиб» у края стекла.
4. **Материал.** Полупрозрачный градиент `rgba(150,172,255,.18)` →
   `rgba(70,96,190,.10)`: стекло пропускает фон. Плюс внутренняя подсветка
   сверху (`inset 0 1px 0 rgba(255,255,255,.42)`) — тонкая светлая кромка,
   внешняя тень на 60 px — глубина, и диагональный блик.
5. **Детали.** Кнопки, поля, переключатель, таблетка статуса и логотип
   получают то же стекло меньшей толщины. Пружинистая анимация
   `cubic-bezier(.34,1.56,.64,1)` на нажатиях, переключателе и смене вкладок.

Раньше стекло считал наш код на процессоре (`ui/`, библиотека walk): три
прохода размытия и выборка с преломлением на каждый кадр — 27 мс на кадр и
шесть кадров в секунду. Страница в Chromium делает то же самое на видеокарте
и без предела в шесть кадров. Пакет `ui/` остался в дереве как запасной
вариант на случай, если WebView2 где-то окажется недоступен.

Логика не зависит от Windows и проверяется тестами `core` (29 проверок:
каталоги и настройки, разбор JSON версии Mojang, сверка SHA-512 модов,
отмена загрузки, подбор Java). Макет старого процессорного стекла можно
получить так:

```bash
GLASS_PREVIEW=aurora/docs/glass-preview.png go test ./ui -run TestGlassPreview
```

## Офлайн-профиль

Кроме входа через Microsoft есть второй способ: вписал имя — и играешь.
Реализовано в `core/offline.go`, в интерфейсе — блок «Офлайн-профиль»
на вкладке «Аккаунт».

```
NewOfflineSession(имя)  →  Session{Offline: true, UUID: OfflineUUID(имя)}
```

- **UUID считается как в самой игре**: `md5("OfflinePlayer:" + имя)` с битами
  версии 3 и варианта RFC 4122 — точный аналог `UUID.nameUUIDFromBytes`.
  Совпадение проверено золотыми значениями, посчитанными независимо
  (модулем `uuid` из Python): `Steve` → `5627dd98-e6be-3c21-b8a8-e92344183641`.
- **Токена нет вообще.** Поэтому в командную строку вместо него подставляется
  `0`, а тип учётной записи ставится `legacy` — игра не пытается обновить то,
  чего нет. Пустоту подставлять нельзя: пустой элемент угодил бы в разбор
  командной строки как лишний аргумент. Тест `TestPlanOfflineArguments`
  проверяет оба режима и отдельно следит, что пустых аргументов нет.
- **Имя проверяется по правилам Minecraft**: 3–16 символов, только латиница,
  цифры и подчёркивание.

Это не обход защиты: одиночная игра и LAN работают, а серверы с проверкой
лицензии (в том числе Realms) такого игрока не пустят — сессию подтвердить
нечем. Интерфейс говорит об этом прямо, до того как игрок нажмёт кнопку.

## Логика

Логика перенесена один в один из прежней версии: те же адреса Mojang и Fabric,
та же раскладка каталогов (`libraries`, `assets`, `versions`), те же ключи
настроек — уже установленная игра подхватывается без переустановки.

Клиентский мод `AetherGlass.jar` вшит в exe (`//go:embed`) и раскладывается
в папку модов при установке: отдельный файл больше не нужен.

## Сборка

```bash
./build.sh
```

Нужен Go 1.23 или новее. Сборка идёт из Linux под Windows, exe появляется
в корне проекта: `AetherGlass-Launcher.exe`.

## Проверка

```bash
go test ./core        # логика: 29 тестов
GOOS=windows go vet ./...
gofmt -l core uiweb .
```

Интерфейс тестами не покрыт: окно нельзя показать без Windows.


## Java для игры: лаунчер ставит её сам

Лаунчеру Java не нужна вовсе — он программа Windows. Java нужна самой игре,
и лаунчер решает вопрос сам, в таком порядке:

1. путь из настроек, если игрок его указал;
2. уже скачанный официальный рантайм Mojang в каталоге игры;
3. **скачивание этого рантайма** (один раз, ~50 МБ, Java 21.0.7);
4. системная Java — только если скачать не удалось вовсе.

От игрока не требуется ничего: никакой «установите Java 21», никакой возни с
JAVA_HOME. Рантайм лежит в каталоге игры и системой не владеет.

### Что было не так раньше

Список рантаймов Mojang устроен не так, как ожидалось: сверху **платформа**,
внутри неё **компонент**, а у каждой сборки — отдельный манифест со списком
файлов. Прежний код искал компонент сверху и потому не находил ничего:
загрузка Java падала, установка прерывалась, и создавалось впечатление, что
«лаунчер не видит Java, хотя она есть». Проверено по живому ответу
launchermeta.mojang.com (тест `TestLiveRuntimeTraversal`):

```
платформа=windows-x64 компонент=java-runtime-delta версия=21.0.7
файлов в манифесте: 484, из них bin/javaw.exe и bin/java.exe
```

Заодно проверены по API и другие детали: версия 1.21.11 действительно
существует и требует `javaVersion.component = java-runtime-delta`
(`majorVersion 21`); последняя стабильная версия Fabric Loader для неё —
0.19.5 (0.20.0 помечена нестабильной). Обе цифры раньше были взяты «из головы».

Системная Java теперь ищется по обоим именам — и `javaw.exe`, и `java.exe` —
плюс по JAVA_HOME, JDK_HOME и каталогам всех распространённых сборок:
прежний поиск видел только javaw и пропускал установки без него.

## Что ускорено (16 октября 2026)

Проверено живым прогоном установки (Linux, чистый каталог): **9,6 с** на всю
игру — клиент, 70 библиотек, 4591 объект ресурсов, профиль Fabric и Java 21;
повторный запуск — 2,7 с (всё из кэша). Моды: 11 штук за 0,19 с, повторно —
0,035 с.

| Было | Стало |
|---|---|
| Пул соединений по умолчанию: 2 соединения на хост → 16 потоков ресурсов всё равно качали по два файла | Свои настройки транспорта: до 64 соединений на хост, живые соединения не рвутся |
| Контрольная сумма считалась вторым проходом по файлу (повторное чтение десятков МБ) | Считается на лету, во время записи: SHA-1 и SHA-512 одновременно |
| Библиотеки (>100 штук) качались по одной | Параллельно, порядок в classpath сохранён |
| Файлы Java-рантайма (136 штук, 103 МБ) качались по одной | Параллельно, крупные — первыми: 1,26 с на весь рантайм |
| Нативные библиотеки распаковывались при каждом запуске | Распаковка помечается контрольной суммой архива и повторно не делается |
| Один и тот же объект ресурсов под разными именами качался дважды | Дубли отбрасываются до начала загрузки |
| Описание версии перекачивалось при каждом запуске | Сохранённый документ живёт 24 часа |
| Любой обрыв сети ронял установку | Обрыв и 5xx повторяются (до 4 попыток с паузой), отмена прерывает их сразу |
| Список модов и поиск Java считались в том же потоке, что и окно | Считаются в фоне, окно не замирает |
| В списке кандидатов Java встречались дубли (лишний запуск `java -version`) | Список очищается от пустых путей и повторов |

Мелочи, которые тоже важны: блок копирования увеличен с 32 КБ до 1 МБ (в разы
меньше системных вызовов при подсчёте сумм), окно дёргается не чаще 10 раз
в секунду, в exe не попадают пути сборочной машины (`-trimpath`).

Новые тесты (всего 27 в `go test ./core`, из них 1 живой сетевой):

- параллельная загрузка: порядок, целостность, «готовый файл не качаем снова»;
- повреждённый файл: ошибка и никакого мусора в каталоге;
- отмена: работа останавливается, возвращается `ErrCancelled`;
- распаковка нативных библиотек: отметка, пропуск, обновление;
- кэш описания версии: свежий читается, устаревший и испорченный — нет;
- человеческие названия модов (не «1.11.3-1.21.11 - Fabric»).

Гонок нет: `go test ./core -race` проходит чисто.

## Оформление: «жидкое стекло» (17 октября 2026)

**Первая попытка — процессором (пакет `ui`).** Интерфейс был переписан
целиком: стандартные кнопки и вкладки Windows в тёмном окне выглядят
чужеродно, поэтому всё рисовалось вручную поверх `walk`. Фон считался в
памяти и становился кистью окна, дочерние элементы с `walk.NullBrush`
наследовали её **со сдвигом по своему положению** — сквозь кнопки было видно
ровно тот кусок фона, что у них за спиной. Стекло каждой детали считалось
отдельно: преломление у кромки, линза на торце, свечение сгиба, диагональный
блик, зерно, прозрачные углы. Работало, но стоило 27 мс на кадр при шести
кадрах в секунду и связывало руки: любую красоту приходилось писать
пикселями на Go.

**Окончательный вариант — видеокартой (пакет `uiweb`).** Окно теперь
открывает движок Chromium (WebView2 входит в Windows 10 и 11), а интерфейс —
обычная страница `uiweb/webui/index.html`, вшитая в exe через `//go:embed`.
То же стекло описывается парой десятков строк CSS и SVG:

| Элемент | Как сделан |
|---|---|
| Карточки и панели | `backdrop-filter` + SVG `feDisplacementMap` для преломления у кромки |
| Кнопки | полупрозрачный градиент, блик сверху, свечение вокруг при наведении, пружинное сжатие при нажатии |
| Полоса хода | дорожка с внутренней тенью, градиентная заливка и блик по верху |
| Переключатель | стеклянный шарик, перекатывается пружиной |
| Список модов | свои строки: цветная точка состояния, название, версия, подсветка под курсором |
| Статус | «таблетка» с дышащей точкой |
| Вкладки | стеклянный указатель, переезжает пружиной |
| Фон | пять размытых пятен, плывут на `transform` — считает видеокарта |

Упругость — пружинной кривой `cubic-bezier(.34,1.56,.64,1)`: элемент чуть
перелетает цель и возвращается. Связь с Go: страница дёргает привязанные
функции (`login`, `install`, `play`, `saveSettings`…), каждый вызов уходит в
свой поток, а ответ приходит одним объектом JSON в `AetherGlass.state`.

Пакет `ui/` не удалён и остаётся запасным вариантом: если на машине нет
WebView2, интерфейс можно вернуть на Win32 одной строкой в `main_windows.go`.
