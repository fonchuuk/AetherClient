# AetherGlass Client 1.0.0 — что сделано и как проверено

Дата отчёта: 16 октября 2026. Minecraft 1.21.11, Fabric Loader 0.19.5,
Fabric API 0.141.6+1.21.11, Java 21, Gradle 9.7.1, Fabric Loom 1.17.21.

## Готовые файлы

| Файл | Размер | Что это |
|---|---:|---|
| `AetherGlass-Launcher.exe` | 10,5 МБ | нативный лаунчер Windows x64. Один файл, Java для него не нужна |
| `AetherGlass.jar` | 240 КБ | мод клиента (Fabric 1.21.11), вшит в exe и раскладывается сам |

Лаунчер — не переименованный jar: это скомпилированный Go- exe (`ui/` на
Win32 через walk, `core/` — логика без интерфейса). Java нужна только игре, и
её лаунчер скачивает сам (официальный рантайм Mojang, Java 21).

### Интерфейс: настоящее жидкое стекло

Фон рисуется в памяти и размывается (переход 39 пикселей), каждая панель,
кнопка, таблетка статуса, поле ввода и логотип берут кусок этого размытого
фона с преломлением у кромок, фокусом, свечением края, бликом, внутренней
тенью и зерном. Проверено не «на глаз», а числами: 12 тестов в
`aurora/launcher-go/ui/glassmath_test.go` (сила размытия, яркость кромки,
преломление у края при его отсутствии в середине, прозрачные углы,
стабильность зерна) и макет окна `aurora/docs/glass-preview.png`.

## Что сделано в этом проходе

### Главное меню — полностью своё, в стиле «жидкое стекло»

* Ванильное меню заменено. На главной странице — крупная стеклянная панель с
  названием и «док» навигации. Стиль один и тот же для меню, настроек и
  списка модулей.
* Кнопки все настоящие: **Одиночная игра** (`SelectWorldScreen`),
  **Сетевая игра** (`JoinMultiplayerScreen`), **Realms**
  (`com.mojang.realmsclient.RealmsMainScreen`), **Настройки**
  (`OptionsScreen`), **Язык** (`LanguageSelectScreen`), **Доступность**,
  **Функции клиента**, **Экранные элементы**, **О клиенте**, **Выход**
  (запрос подтверждения через `ConfirmScreen`). Все классы и конструкторы
  сверены разбором байткода игры 1.21.11, а не взяты из памяти.
* Заголовок рисуется посимвольно — получается настоящий градиент без шейдеров.
* Реакция на наведение и нажатие, «чик»-подсветка, мягкое появление — всё от
  времени кадра, поэтому одинаково на 30 и на 300 кадрах в секунду.

### Зимняя ночь и атмосферные надписи

* Фон: холодный градиент ночи, сияние над горизонтом, ореол луны, редкие
  стеклянные пластины и медленный снегопад на собственной текстуре
  (`assets/aetherglass/textures/particle/circle.png`).
* Надписи — одиннадцать заданных фраз, дословно. Они медленно дрейфуют,
  плавно появляются и гаснут, чуть отодвигаются от курсора (не больше чем на
  13 пикселей) и **не заходят на панели и кнопки**: место выбирается сразу с
  учётом всего будущего пути надписи, а не «по ходу».
* Никаких настроек у надписей нет — включить, выключить или изменить их
  количество нельзя, так и задумано.
* Порядок фраз: каждая следующая берётся из «мешка», поэтому повтор одной и
  той же фразы возможен не раньше чем через четыре показа.

### Установщик `AetherGlass-Setup.exe`

Новый модуль `installer` (1 354 строки, 38 тестов). Что он реально делает:

* кладёт `AetherGlassLauncher.exe` и копию себя (`AetherGlass-Uninstall.exe`)
  в `%LOCALAPPDATA%\AetherGlass`;
* создаёт ярлыки на рабочем столе и в меню «Пуск» сценарием VBScript через
  `cscript` — по-другому `.lnk` из Java без сторонних библиотек не создать;
* пишет запись в «Программы и компоненты» штатной `reg.exe`: название, версия,
  издатель, иконка, команда удаления и команда восстановления;
* отличает чистую установку от обновления (по `install.json`) — при обновлении
  файлы заменяются, настройки и аккаунты остаются;
* удаляет установленное: файлы из манифеста, ярлыки, запись в реестре,
  каталог; настройки по умолчанию сохраняются;
* проверяет наличие Java 21 (`JAVA_HOME`, PATH, типовые каталоги) и честно
  предупреждает, если её нет: установка не «делает вид», что всё хорошо;
* умеет работать без окон (`--console`) и по ключам `--uninstall`, `--repair`.

### Хранение токенов

На Windows файл с токенами теперь закрывается от других пользователей:
наследование прав отключается, полный доступ выдаётся только текущему
пользователю (`icacls … /inheritance:r /grant:r <пользователь>:F`). На Linux и
macOS права 600 были и раньше. Проверено тестом на настоящем файле.

### Иконки

Обе иконки (лаунчер и установщик) нарисованы своим скриптом
`tools/make_icon.py`: тёмное стекло, холодный градиент, блик по кромке,
буква «А» у лаунчера и коробка со стрелкой у установщика. Формат `.ico` с
набором размеров 16…256.

Minecraft не доходит даже до главного меню, а значит такой «проверке» верить
нельзя. Проверка идёт по коду, байткоду, тестам и разбору готовых файлов.

## Что не сделано и не выдаётся за сделанное

* **Режимы эффектов и менеджер материалов.** Требуются режимы
  Outline / Fill / Shader Fill / Rainbow / Custom Color для рук и блоков,
  градиенты для неба и свой менеджер материалов с сохранением. Сейчас есть
  геометрический контур блока по реальной `VoxelShape`, эффекты рук и радуга,
  но полного набора режимов и менеджера материалов **нет**.
* **Переключатель аккаунтов внутри игры** отсутствует.
* **Установщик не запускался на настоящей Windows**: сборка идёт на Linux.
  Проверена логика (38 тестов), состав команд `reg.exe`, текст сценария
  ярлыков и сами файлы — но не поведение Windows.
* **14 фотографий для точной стилизации** так и не присланы: внешний вид меню
  сделан по описанию «жидкое стекло / iOS 26», а не по образцу.
* Подписи `.exe` нет: без сертификата антивирусы иногда ругаются на
  самораспаковывающиеся файлы. launch4j и сам предупреждает об этом при сборке.

## Как установить

1. Взять `dist/AetherGlass-Setup.exe`.
2. Запустить: указать каталог (по умолчанию `%LOCALAPPDATA%\AetherGlass`),
   отметить ярлыки — установщик положит лаунчер и создаст запись в
   «Программы и компоненты».
3. В лаунчере: войти в аккаунт Microsoft (XBL → XSTS → Minecraft), выбрать
   версию 1.21.11, установить Fabric и 10 модов оптимизации, нажать «Играть».

Для удаления: «Параметры» → «Приложения» → **AetherGlass Launcher** →
«Удалить». Настройки и аккаунты останутся в `%APPDATA%\AetherGlass`.

### Полная поставка: установщик со своей Java (16 октября 2026)
Причина двух окон на Windows («Помощник по совместимости» и «установите Java с
adoptium.net») найдена и устранена полностью:

- У exe не было манифеста приложения. Windows считает такой файл «установщиком
  старого типа» (имя со словом Setup) и следит за ним; раз записи в
  «Программы и компоненты» не появилось, он показывает «программа установлена
  неправильно». В оба exe встроен манифест: `requestedExecutionLevel`,
  `supportedOS` для Vista…Windows 11, `PerMonitorV2` для чёткого интерфейса на
  масштабированных экранах.
- В сообщениях launch4j и в ссылке `downloadUrl` был Adoptium. Теперь там
  нейтральная формулировка и `https://openjdk.org/install/` — никакой рекламы
  конкретного поставщика.
- Сам установщик — программа на Java, поэтому на компьютере без Java 21 он
  вообще не запускался. Теперь есть полная поставка: `AetherGlass-Setup-full.zip`
  рядом с exe содержит собственный рантайм (jlink, 48 МБ). Установщик
  запускается на нём, а при установке копирует его в каталог программы —
  после этого и лаунчер не зависит от системной Java.

Обычный `AetherGlass-Setup.exe` (0,6 МБ) остался: он подходит, если Java 21 на
компьютере уже есть. Для игры по-прежнему берётся системная Java 21 либо
официальный рантайм Mojang, который лаунчер скачивает при установке игры.

### Автономный лаунчер: просто exe, без установщика (16 октября 2026)
Установщик — вещь полезная, но лишняя, когда нужно просто запустить и поиграть.
Поэтому основная поставка теперь такая: `AetherGlass-Launcher.zip` — внутри
`AetherGlassLauncher.exe`, каталог `runtime` (своя Java 21, 49 МБ, сборка
OpenJDK) и `AetherGlass.jar` (мод клиента). Распаковал, запустил exe — и всё,
ничего устанавливать не надо, Java на компьютере не нужна.

Что для этого сделано в коде:
- `launch4j` ищет Java в каталоге `runtime` рядом с exe, а не только в системе;
- в exe встроен манифест приложения (`requestedExecutionLevel`, `supportedOS`,
  `PerMonitorV2`) — Windows перестаёт принимать его за установщик старого типа;
- `LauncherUi.findClientModJar()` ищет собранный мод не только в каталоге
  сборки проекта, но и рядом с exe — для автономной поставки это единственный
  способ подложить клиент в игру;
- каталог `runtime` собран через `jlink` ровно из тех модулей, которые реально
  нужны лаунчеру: `java.base`, `java.desktop`, `java.net.http`,
  `java.logging`, `java.xml`, `jdk.crypto.ec`, `jdk.unsupported`,
  `java.management`, `jdk.httpserver`, `jdk.management`. Список проверен
  `jdeps`: модули `jdk.httpserver` (локальный сервер входа Microsoft) и
  `jdk.management` (`com.sun.management.OperatingSystemMXBean` — объём памяти)
  легко потерять, без них лаунчер падает сразу после появления окна.

Сборка только лаунчера занимает 17 секунд — но лишь с `--configure-on-demand`:
без него Gradle настраивает и модуль клиента, а Fabric Loom на холодном кэше
съедает всю память (2 ГБ) и сборка гибнет.

### Один exe вместо архива (16 октября 2026)
Архив — это лишнее действие, поэтому основная поставка теперь одним файлом:
`AetherGlass-Launcher.exe` (31 МБ). Это самораспаковывающийся архив: модуль
`7zSD.sfx` из LZMA SDK 26.04, к нему приписан конфиг

    ;!@Install@!UTF-8!
    Title="AetherGlass Launcher"
    RunProgram="AetherGlassLauncher.exe"
    ;!@InstallEnd@!

а дальше — сам архив. Поведение модуля проверено по исходнику
`CPP/7zip/Bundles/SFXSetup/SfxSetup.cpp`: без `BeginPrompt` он молча
распаковывается во временную папку `7zS*`, запускает указанную программу,
ждёт её завершения (`WaitForSingleObject`) и только потом удаляет временную
папку. Данные игры при этом лежат в `%USERPROFILE%\.aetherglass`, поэтому
ничего полезного не удаляется.

Распаковка 50 МБ занимает несколько секунд при каждом запуске — это цена
одного файла. Кому важно мгновенное включение, есть `AetherGlass-Launcher.zip`:
распаковал один раз и запускаешь exe уже без распаковки.

Отдельно про «Помощник по совместимости»: у самого модуля `7zSD.sfx`
манифеста нет, но эвристика Windows срабатывает в первую очередь на слова
setup/install/update в имени файла и в полях версии — здесь имени
`AetherGlass-Launcher` и полей Igor Pavlov это не касается. Внутренний
`AetherGlassLauncher.exe` манифест имеет.
### Почему exe не запускался: нет Main-Class в манифесте (16 октября 2026)
Симптом: `Java Virtual Machine Launcher — Error: Unable to access jarfile
…\Temp\7zS*\AetherGlassLauncher.exe`. Причина нашлась запуском
`java -jar AetherGlassLauncher.exe` в Linux: JVM читает exe как архив
(launch4j приклеивает jar к exe), но внутри манифест содержал только
`Manifest-Version: 1.0` — плагин `application` прописывает `Main-Class`
исключительно в стартовые скрипты, а в сам jar — нет. Что сделано:

- в `launcher/build.gradle` jar получил явный `Main-Class` и фиксированное имя
  `AetherGlassLauncher.jar` (чтобы путь не зависел от версии);
- launch4j переведён на внешний jar (`<dontWrapJar>true</dontWrapJar>`),
  jar кладётся рядом с exe: JVM читает обычный zip-файл, а не exe, который в
  момент запуска может держать антивирус. Из-за этого exe «похудел» до 134 КБ
  и один без jar не работает — exe и jar всегда идут парой;
- установщик и задача `dist` тоже копируют jar рядом с exe.

Проверено: `java -jar AetherGlassLauncher.jar` доходит до создания окна
(в песочнице падает на `HeadlessException`, то есть класс найден и загружен),
28 тестов лаунчера — без падений.

### Лаунчер переписан: нативный exe вместо Java (16 октября 2026)
Главная претензия была справедливой: exe, внутри которого jar, — это не
программа Windows, а костыль. Лаунчер переписан на Go и собирается в настоящий
exe (10,6 МБ): интерфейс на Win32 через walk, никакой Java, никаких jar,
никакого каталога `runtime` рядом. Исходники — `launcher-go/`.

Что это меняет:
- exe один и запускается мгновенно, а не распаковывает 50 МБ при каждом старте;
- Java не нужна лаунчеру вообще. Она нужна только игре, и если в системе её
  нет, лаунчер скачает официальный рантайм Mojang при установке игры;
- клиентский мод вшит в exe и раскладывается в папку модов сам;
- манифест Windows (requestedExecutionLevel, supportedOS, PerMonitorV2,
  общие элементы управления 6-й версии) вшит в exe — «Помощник по совместимости»
  больше не появляется.

Логика перенесена полностью: те же адреса Mojang и Fabric, та же раскладка
каталогов, те же ключи настроек. Всё, что можно проверить без Windows,
проверяется тестами: `go test ./core` — 12 тестов, `GOOS=windows go vet ./...`
чисто. Окно целиком протестировать нельзя: для этого нужен Windows.

По ходу тесты поймали настоящий баг: `best.Valid()` для пустой структуры
возвращал true, и лаунчер мог «найти» Java по пустому пути.
### Почему лаунчер «не видел» Java, даже когда она была (16 октября 2026)
Причина нашлась только проверкой по живому API Mojang. Список рантаймов
устроен так: платформа → компонент → сборки, и у каждой сборки отдельный
манифест со списком файлов. Код обходил его наоборот (компонент → платформа)
и не находил ничего, поэтому скачивание Java падало, установка обрывалась,
а игрок видел сообщение про Java. Теперь:

- обход индекса исправлен и покрыт тестом, который обращается к настоящему
  адресу Mojang (при отсутствии сети тест пропускается);
- Java по умолчанию не ищется в системе вовсе: лаунчер скачивает официальный
  рантайм Mojang (Java 21.0.7) в каталог игры. Системная Java — крайний
  вариант, если скачать не удалось;
- в интерфейсе появилась вкладка «Java»: видно, какая Java будет использована,
  откуда она и можно перекачать её заново;
- версия Fabric Loader взята с API Fabric, а не из головы: 0.19.5 (0.20.0 для
  1.21.11 помечена нестабильной);
- системная Java ищется по обоим именам — javaw.exe и java.exe — иначе
  установки без javaw оставались незамеченными.

### Оформление «жидкое стекло» и правка Java (17 октября 2026)

**Интерфейс лаунчера переписан.** Стандартные кнопки, вкладки и полоса
загрузки Windows заменены нарисованными вручную: скруглённые стеклянные
карточки со светлой кромкой, кнопки-таблетки с пружинным нажатием и мягким
свечением, своя полоса хода с бегущим бликом, стеклянный переключатель,
«таблетка» статуса с дышащей точкой, свой список модов, весь текст печатается
на стекле. За окном — живой фон: медленно плывущие размытые пятна. Прозрачность
настоящая: дочерние элементы берут кисть родителя со сдвигом (`walk.NullBrush`),
поэтому фон просвечивает сквозь кнопки. Окно получает скруглённые углы и
акриловую подложку Windows 11 и рисуется в двойном буфере. Подробности —
в `launcher-go/README.md`, раздел «Оформление: жидкое стекло».

**Про Java — уточнение, которое важно:** сам лаунчер Java не требует вообще
(это нативный exe). Java нужна только игре, и лаунчер по-прежнему качает
официальный рантайм Mojang в каталог игры. Доправлено: если `javaw.exe`
(Java без консольного окна) не печатает версию в канал — а такое бывает, —
версия спрашивается у соседнего `java.exe`, а путь для запуска остаётся
прежним, чтобы рядом с игрой не появлялось пустое чёрное окно
(`core.consoleSibling`, тесты `TestConsoleSibling` и
`TestInspectFallsBackToConsoleJava`).
