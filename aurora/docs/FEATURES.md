# Что реализовано

Всё ниже — рабочий код из этого репозитория. Ничего не «заглушено»,
нет ни одного `TODO`, нет методов-пустышек и нет кнопок, которые ничего не делают.

---

## 1. Собственный главный экран

| | |
|---|---|
| Экран | `gui/screen/AuroraMenuScreen` |
| Открывается | вместо ванильного меню (миксин в `Minecraft.setScreen`), а также по клавише `Right Shift` |

Три страницы, переключаются кнопками сверху:

- **Главная** — название, версия, кнопки «Одиночная игра», «Сеть», «Настройки»,
  «О клиенте» (все четыре открывают настоящие экраны игры), «Выход».
- **Функции** — карточки всех восьми модулей: переключатель, описание, кнопка
  в экран настроек модуля.
- **Настройки** — все настройки модуля «Оформление» на одной странице:
  палитра, оттенок, плотность стекла, радиус, скорость анимаций,
  своё меню, анимированный фон, стекло в HUD.

Фон: animated gradient (плавный градиент по времени) + мягкие «блики» и свечение.
Его можно отключить (`Анимированный фон`) — тогда рисуется статичный градиент.

**Анимации от времени, не от кадров.** У каждого виджета есть своё состояние
(`AuroraWidget.tickAnimation`), которое считается через `AnimationTimer` с дельтой
кадра. Это значит, что меню одинаково выглядит и на 30, и на 240 fps
(проверено тестом: 60 мелких шагов дают тот же результат, что один крупный).

**Эффект «жидкого стекла»** (`DrawUtil.glassPanel`): многослойная панель —
подложка с альфой, тонкая светлая линия сверху (блик), тёмная снизу,
цветная окантовка с акцентом и мягкое свечение вокруг. Плотность, радиус
и цвет берутся из темы, поэтому меняются «на лету».

**Отклик на нажатие** — ripple: круг, который расходится от точки клика
и затухает (`AuroraButton` + `AuroraWidget.pressAnimation`). Рисуется в том же
проходе, что и сама кнопка, без дополнительных проходов рендера.

## 2. Система модулей

- `Module` — имя, описание, категория, список настроек, включение/выключение.
- `ModuleManager` — регистрация, включение, покадровое обновление
  (`update(delta)` вызывается ровно один раз за кадр из `WorldRenderDispatcher`).
- Настройки: `BooleanSetting`, `IntSetting`, `FloatSetting`, `ColorSetting`,
  `EnumSetting` — у каждой есть ключ, название, описание, значение по умолчанию,
  границы и проверка. Экран настроек (`ModuleSettingsScreen`) **строится автоматически**
  по списку настроек — для нового модуля не нужно писать ни строчки интерфейса.
- Выключение модуля освобождает ресурсы: пул частиц очищается, буфер вершин
  освобождается, обработчики не остаются висеть.
- `InterfaceModule` нельзя выключить (`canBeDisabled() == false`) — он отвечает
  за тему, без неё интерфейс потерял бы цвета.

### Модули

| Модуль | Настройки |
|--------|-----------|
| **Оформление** | палитра (тёмная/светлая), оттенок акцента, плотность стекла, радиус, скорость анимаций, своё меню, анимированный фон, стекло в HUD |
| **Частицы** | форма, пресет, начальный и конечный цвет, размер, прозрачность, появление/затухание, скорость, время жизни, тяга, частота, предел, след за игроком, только в движении |
| **Эффекты блоков** | подсветка блока, цвет, толщина контура, плотность, скорость пульсации, частицы при ударе, число частиц, разлёт, частицы у блоков, радиус поиска, частота, блоков за раз, и группы блоков: руды / хранилища / источники света / растения |
| **Эффекты рук** | стиль (свечение, контур, градиент, нет), движение, цвет, интенсивность, скорость появления, сила размаха |

| **Экранный интерфейс** | по отдельному переключателю на каждый из 15 элементов HUD |

## 3. Визуальные эффекты

### 3.1 Частицы (`render/particle`)

- 6 форм: круг, квадрат, звезда, кольцо, сердце, искра. Текстуры генерируются
  скриптом `tools/gen_particle_textures.py` (честно рисует PNG), а не взяты из игры.
- Цвет: плавный переход от начального к конечному цвету за время жизни.
- Размер и прозрачность: настраиваются, частица появляется и затухает
  (параметр «Появление и затухание» задаёт долю времени на эти фазы).
- Пул фиксированного размера (по умолчанию 1 500, минимум 16) — **без аллокаций
  в цикле**: удаление через swap, объекты переиспользуются.
- 6 пресетов: обычный, снег, угольки, магия, дым, сердца.
- Рендерятся **в мире** (`WorldRenderEvents.BEFORE_TRANSLUCENT`), а не в GUI:
  со смещением камеры, в правильном слое прозрачности, с отсечением по расстоянию (32 блока).

### 3.2 Эффекты блоков (`render/block`)

- Подсветка блока под прицелом строится по **настоящей геометрии блока**:
  рёбра берутся через `VoxelShape.forAllEdges`, объём — через `VoxelShape.forAllBoxes`.
  Поэтому у плиты, ступеньки, лестницы, забора и стекла контур повторяет их
  настоящую форму, а не общую рамку блока. Общие рёбра соседних параллелепипедов
  формы склеиваются (ключ ребра), чтобы контур не рисовался дважды.
  Геометрия кэшируется по состоянию блока — в кадре нет ни выделений, ни пересчёта.
- **Режимы заливки** (настройка «Режим заливки»):
  - `Контур` — только рёбра формы: обзор ничем не перекрывается;
  - `Заливка` — полупрозрачные грани формы ровным цветом;
  - `Градиент` — «жидкое стекло»: вертикальный градиент по каждой грани плюс
    бегущий блик. Яркость верхней кромки идёт по синусу от времени, низ
    затемняется к чёрному. Градиент задаётся цветами вершин
    (`ShapeBuffer.addGradientBoxFaces`): ни текстур, ни шейдерных пакетов.
- **Источник цвета** — одной настройкой: свой цвет, общая радуга (из единого
  `ColorController`) или акцент оформления клиента.
- Отдельно настраиваются плотность заливки, толщина и яркость контура,
  свечение (мягкий ореол: те же грани, расширенные на 0,03 блока и сильно
  прозрачные), скорость блика, блик по верхней кромке и пульсация.
- **Материалы** (`render/material`): режим, источник цвета, цвет, плотность,
  толщина и яркость контура, свечение, скорость блика и кромка сохраняются
  одним набором под своим именем. Пять стандартных материалов идут с клиентом;
  любой можно изменить, скопировать под новым именем, удалить или вернуть к
  стандартным. Выбор и правки лежат в файле настроек и читаются при запуске;
  испорченные значения обрезаются по диапазону, а не ломают клиент.
  Экран — «Материалы» в главном меню.
- Пульсация яркости по времени, настраиваемая скорость.
- Частицы при ударе по блоку — со счётчиком и пределом, без бесконечного спавна.
- Частицы вокруг блоков по группам (руды, хранилища, источники света, растения):
  радиус поиска, частота, максимум блоков за раз (24).
- Игровые свойства блока **не меняются** — меняется только отрисовка.

### 3.3 Эффекты рук (`render/hand`)

- Отрисовываются **поверх уже нарисованной ванильной руки и предмета**
  (миксин в `ItemInHandRenderer.renderHandsWithItems`, вызов идёт после `ci`),
  а не вместо неё. Рука остаётся настоящей трёхмерной моделью.
- Стили: свечение, контур, градиент, нет.
- Анимация появления/исчезновения руки и сила размаха — через `AnimationTimer`.
- Цвет и интенсивность настраиваются; при включённой радуге цвет берётся из
  общего контроллера.

### 3.4 Эффекты неба (`render/sky`)

- Миксин в `SkyRenderer.extractRenderState` меняет цвета неба **в мире**,
  а не накладывает плёнку на экран.
- Пресеты: сияние, закат, океан, пустота, свой (два цвета).
- Плавный переход цвета по времени, скорость и интенсивность настраиваются.
- **Без шейдеров**: это изменение параметров состояния рендера неба,
  а не шейдерный пакет.

### 3.5 Радуга (`render/ColorController`)

- Один-единственный контроллер цвета. Все эффекты (частицы, блоки, руки, небо)
  берут цвет из него — `ColorController.hsb()` / `ColorController.argb()`.
- Скорость, интенсивность, насыщенность, яркость; отдельный флаг «влияет на небо».
- Цвет считается один раз за кадр, а не для каждой частицы.

## 4. Наэкранный интерфейс (HUD)

15 элементов, каждый включается отдельно и перетаскивается мышью
в экране `HudEditorScreen` (открывается из «О клиенте» → «Редактор HUD»):

логотип, кадры в секунду, производительность, координаты, направление,
время, биом, время в мире, эффекты (зелья), цель, предмет в руке,
снаряжение, стрелы, нажатия клавиш, клики в секунду.

- Позиции хранятся в **долях экрана** (0..1) — при смене разрешения или
  масштаба GUI элементы остаются там, где их поставили.
- Редактор показывает ровно то, что будет в игре: и там, и там рисует
  один и тот же `HudPainter`.
- «Производительность» показывает реальные цифры: fps, использование памяти,
  задержку кадра, число частиц.
- Подложка — «жидкое стекло» с настраиваемой плотностью.

## 5. Конфигурация

- Свой каталог: `~/.aetherglass/` (в игре — `run/config/aetherglass`).
- Один файл `aetherglass.json`, человекочитаемый, с отступами.
- Хранится: включённость модулей, все настройки (цвета, пресеты, параметры
  анимаций, интенсивность), позиции HUD, настройки интерфейса.
- Ключи: `module.<id>.enabled`, `module.<id>.setting.<key>`, `hud.pos.<id>.x/.y`.
- При повреждении файла клиент не падает: читает по ключам, битое значение
  заменяется на значение по умолчанию, при следующем сохранении файл
  перезаписывается целиком.
- Настройки применяются сразу, без перезапуска (тема, цвета, пределы, HUD).
- Запись на диск — только при изменении, не чаще раза в секунду, через
  временный файл и атомарную подмену. В цикле рендера обращений к диску нет.

## 6. Лаунчер

- Вкладки: **Игра**, **Моды**, **Настройки**, **Логи**.
- **Игра**: список версий из официального манифеста Mojang (показывается 1.21.11),
  кнопка установки/проверки, кнопка «Играть» с защитой от повторного запуска,
  состояние входа в аккаунт.
- **Моды**: список из `launcher/src/main/resources/mods.json` — 10 оптимизационных модов
  + Fabric API + сам мод клиента; для каждого показывается версия, статус файла
  и контрольные суммы.
- **Настройки**: объём памяти (с границами), путь к Java (с проверкой версии),
  каталог игры, параметры окна.
- **Логи**: просмотрщик логов с фильтром и сохранением в файл.
- Установка: клиент Minecraft, библиотеки, ресурсы (параллельно), профиль
  Fabric Loader, моды — с прогрессом и **отменой** (кнопка «Отмена» реально
  прерывает скачивание, а не просто прячет прогресс).
- Проверки перед запуском: есть ли Java 21+, есть ли файлы, есть ли доступ
  к каталогу, не запущена ли игра уже.
- Понятные ошибки: «не найден файл X», «несовместимая Java: нужна 21+, найдена 11»,
  «нет доступа к каталогу», «нет интернета» — каждая с указанием, что делать.
- Ограничение безопасности: скачиваются только файлы из официального манифеста
  Mojang и с Modrinth по контрольным суммам SHA-512 из нашего манифеста.
  Никаких запускаемых файлов из неизвестных источников.

## 7. Вход в аккаунт

Реальный официальный поток (не имитация):

```
Microsoft OAuth 2.0 (device code)
        ↓
Xbox Live  (user.auth.xboxlive.com/user/authenticate)
        ↓
XSTS       (xsts.auth.xboxlive.com/xsts/authorize)
        ↓
Minecraft  (api.minecraftservices.com/authentication/login_with_xbox)
        ↓
Профиль    (api.minecraftservices.com/minecraft/profile)
```

- Пароль нигде не вводится и не хранится — только код устройства
  и токены в `~/.aetherglass/auth.json`.
- Токены проверяются на срок действия, при истечении — обновление.
- Требуется идентификатор приложения Azure (`auth/MicrosoftClientId`).
  Без него поток невозможен — это ограничение описано в
  [`docs/LIMITATIONS.md`](LIMITATIONS.md) явным текстом, без «заглушек».

## 8. Проверка окружения

- **Манифест версий Mojang** — реальный запрос: 1.21.11 существует.
- **Fabric Loader** — реальный запрос к `meta.fabricmc.net`: 0.19.5.
- **Fabric API** — реальный запрос к Modrinth: 0.141.6+1.21.11.
- **Java** — версия берётся из `javaVersion.majorVersion` в JSON версии: 21.
- **Маппинги** — Yarn для 1.21.11 отсутствует (meta.fabricmc.net отвечает
  `Not Found`), поэтому используются официальные маппинги Mojang.
- **Сигнатуры методов** — сверены по байткоду самой игры (`javap` по
  `minecraft-named.jar`) и по исходникам Fabric API: `MultiBufferSource`,
  `GuiGraphics`, `ItemInHandRenderer`, `SkyRenderer`, `AbstractWidget`,
  `MouseButtonEvent`, `KeyEvent` и другие.

Одиннадцать заданных фраз, дословно. Медленный дрейф, плавное появление и

иконка, свойства файла, проверка версии Java, защита от второго запуска.
Не переименованные jar.

## Добавлено 16.10.2026

### Режимы заливки и материалы
Пять режимов из задания закрыты полностью: контур, заливка, градиент
(«шейдерная» заливка без шейдеров — градиент по вершинам), радуга и свой цвет.
У каждого режима свои настройки, а весь набор сохраняется материалом под своим
именем (см. раздел 3.2). Экран материалов открывается из главного меню; правка
применяется к блоку сразу, без перезапуска.

### Упругое меню
Элементы меню больше не двигаются по готовым кривым: у каждого три пружины —
наведение, нажатие и появление. Пружина считается как настоящий затухающий
осциллятор с фиксированным внутренним шагом 1/240 с, поэтому движение
одинаково и на 30, и на 300 кадрах в секунду (есть отдельный тест). Нажатие
задаётся импульсом, а не анимацией «туда-обратно», поэтому элемент сжимается
и сам выпрыгивает обратно с перелётом. Сила пружинистости — настройка
«Пружинистость» (0…1) в модуле «Оформление»: она меняет демпфирование, а не
просто длительность.

### Java для игры: своя или официальный рантайм Mojang
Лаунчер больше не требует, чтобы игрок сам ставил Java, и не тащит никаких
сторонних установщиков. Порядок такой: своя Java (путь из настроек, затем
`JAVA_HOME`, `PATH` и каталоги установки любых сборок) — её и используем;
нет или старая — берём уже скачанный официальный рантайм Mojang в каталоге
игры; нет и его — скачиваем при установке игры ровно тот компонент, который
указан в JSON версии (`javaVersion.component`, для 1.21.11 это Java 21).
Источник — официальный список рантаймов Mojang, файлы проверяются по SHA-1,
загрузку можно отменить. Установщик при этом ничего не скачивает и ни на
какой сайт не ссылается.

### Оформление лаунчера и установщика
- Один визуальный язык на три окна: клиент, лаунчер, установщик. Набор
  компонентов — `launcher/ui/UiKit`, установщик использует его же.
- Фон — градиент с тремя медленно дрейфующими световыми пятнами; панели —
  «стекло» со скруглением 18 px и подсветкой по верхней кромке.
- Кнопки рисуются кодом: градиент, свечение при наведении, упругое нажатие
  с перелётом по той же кривой, что и в меню игры.
- Вкладки — «таблетки», индикатор загрузки — скруглённая дорожка с градиентным
  заполнением, ползунок памяти — свой, таблица модов — с цветными состояниями
  («установлен», «отсутствует», «устарел»).
- Все анимации идут от одного таймера 30 Гц: он перерисовывает только те
  компоненты, у которых есть незавершённое движение, и выключается, когда
  движение закончилось.
- Оба окна (лаунчер и установщик) умеют печататься в PNG без графического
  окружения: `UiPreview` и `InstallerPreview`. Разметка проверяется по снимкам,
  без запуска Windows.
